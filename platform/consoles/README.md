# Console release packages

The main Build Artifacts workflow calls `console-artifacts.yml` for PS1, PS2,
PSP and 3DS on default-branch pushes, version tags and pull requests. Each platform has its own Docker target,
SDK and artifact. Successful default-branch builds attach all four packages to
the rolling `pre-release`; version tags attach them to the tagged release.
Pull requests produce Actions artifacts without replacing
the rolling release. The reusable workflow can also be dispatched to build only
the console packages.

| Download | Contents | Launch |
| --- | --- | --- |
| `rfvp-ps1.zip` | `rfvp.bin`, `rfvp.cue`, PS-X EXE, disc source files | Boot the CUE; stock 2 MiB runtime |
| `rfvp-ps2.zip` | ISO, ELF, converted demo | Boot the ISO, or the ELF with a host/USB game directory |
| `rfvp-psp.zip` | `PSP/GAME/RFVP/EBOOT.PBP` and demo | Copy to the memory stick and launch as homebrew |
| `rfvp-3ds.zip` | `3ds/rfvp/rfvp.3dsx` and `game/` | Copy to the SD card and use Homebrew Launcher |

Packages contain a small original RFVP demo generated by `make-demo.py`. They
contain no commercial game assets. Their README explains replacing the demo
with a user's own converted game. The demo exercises script loading, picture
conversion, primitive rendering and a yielding VM loop. It is a boot scene,
not a full gameplay compatibility test. Every ZIP includes its source commit,
engine version, license and per-file SHA256 hashes. Binary signatures and disc
formats are checked before upload; missing executables fail the job.

## Separate toolchain images

After a successful default-branch package build, CI publishes
`ghcr.io/OWNER/rfvp-PLATFORM-builder:COMMIT` and `:latest`, where PLATFORM is
`ps1`, `ps2`, `psp` or `3ds`. Builds do not depend on a pre-existing GHCR image:
they build the Docker target first, with a separate Actions layer cache for each
platform. Pull requests also work before any image has been published.

`platform/docker/Dockerfile.console` has four independently selected targets:

- PS1: PSn00bSDK 0.24 with its MIPS GCC and LLVM 23.
- PS2: ps2dev v2.0.0 (ps2sdk and gsKit), LLVM 23, and xorriso for ISO packaging.
- PSP: PSPDEV v20261001, cargo-psp 0.2.8 and nightly-2025-03-19.
- 3DS: the dated official devkitPro/devkitARM image 20260610 with libctru/citro3d.

The main Rust nightly is read from `toolchain.env`; the PSP/PS2 legacy nightly is
installed only in those two targets. Host converters use stable Rust to avoid
mixing prebuilt std with the repository's nightly build-std configuration.
LLVM uses the official LLVM 23 branch
repository and can receive patch updates between clean image rebuilds. SDK versions are pinned,
but the entire image is not byte-reproducible. Published commit tags identify the
exact validated image for a particular build. No BIOS or DSP firmware is bundled.

## Local build

From the repository root, with Docker installed:

```sh
docker build --target console-ps1 -f platform/docker/Dockerfile.console \
  -t rfvp-console:ps1 platform
docker run --rm -v "$PWD:/work" -w /work rfvp-console:ps1 \
  bash platform/consoles/build-package.sh ps1
```

Replace `ps1` with `ps2`, `psp` or `3ds`. The package appears in
`dist/consoles/rfvp-PLATFORM.zip`; intermediate output is isolated under
`target/console-PLATFORM`. Existing converted games are not input to CI.

The existing mixed console image and the Switch/Vita workflows are independent
of this workflow. Wii is outside the scope of these four release packages.
